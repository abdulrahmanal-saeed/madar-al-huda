# Fiqh source library

All source changes are drafts. No changes to the editorial publishing role or existing issue completeness gates; source validation is now type-specific. There is no religious certification from metadata entry. Do not guess editions, authors, grading, or locators.

- Create: fiqh_create_source {record, ownerConfirmed:true}; get: fiqh_get_source {id}; update: fiqh_update_source {record, expectedToken, ownerConfirmed:true}.
- Bulk: fiqh_bulk_upsert_sources {rows:[{record, expectedToken}], preview:true/false, ownerConfirmed:false/true}. Null token creates; exact token updates. Full records, max 50/512 KiB, atomic. Preview rolls back. Explicit owner approval before commit. Admin bulk JSON uses the same rows and confirmation checkbox.
- Fields: id, bilingual title/author/editor, madhhab (one school or null), sourceType, publisher, edition, publicationYear, URL, license, volume/pages/chapter/section, editorialNotes, status placeholder/draft, documentationStatus pending/documented. New Quran source has no human author or madhhab; no edition or license required for canonical Quran reference. Hadith collection and book require author, edition, publisher and license; investigator/year/link optional if known. Pending/placeholder remains incomplete. Legacy draft records without documentationStatus retain existing bibliographic requirements. No source data is seeded or inferred.
- Quran evidence uses quran source plus existing validated surah/firstAyah/lastAyah. Hadith uses hadith_collection source plus bilingual book, edition locator, number or chapter (unnumbered editions supported), grading and grading attribution. Existing issue requirements remain. Historical public projection does not impose new cross-type requirements retroactively.
- Source updates refresh the latest linked draft revisions within the same transaction. The canonical issue body, ID, slug, number and existing published pointer stay unchanged. Recheck errors using the new frozen source snapshot. Previously published snapshots do not change until republished.
- Admin missing source paths link to the source JSON editor; issue paths jump to the relevant editor field or JSON group. No changes to live data as part of this PR; the nine existing issues remain in production. Integration/CI and device/browser verification are required before rollout.
