# FIQH-DEV-06 — mobile reader foundation

New client contract: GET /admin/?feed=fiqh, application/json, schemaVersion 1, kind "published_fiqh", bilingual disclaimer, categories with id and bilingual title, issues with id, categoryId, revision (positive integer), status "published", title, four school positions keyed by stable school IDs, optional canonical display fields and a sources map keyed by source ID. The server projection has not been implemented yet; this is a proposed contract for the following phase. The client rejects unsupported, draft, duplicate or incomplete-school records. The authoritative server must enforce scholarly approval; client shape checks are not proof of authenticity.

The new provider reuses the existing HTTPS HostedFeed, ETag, bounded cache, foreground and 15-minute refresh. While the new feed is absent or unavailable without a validated cache, the existing legacy screen is used. A valid empty feed is authoritative, not a signal to fall back. An offline saved catalog can retain prior approved data until sync. Existing managed release gating remains.

Initial Flutter UI: category filters and published counts, bilingual normalized title/summary/keyword search, issue detail, fixed four-school order, explanation and reasoning, evidence, grading attribution, agreement/disagreement/reasons, frozen source title and locator display, copy issue reference. Theme and direction follow the app. Remaining: bookmarks/history, system sharing, dedicated side-by-side/adaptive comparison, source/evidence navigation, all optional structured fields, localized generated strings, font settings, related issues and accessibility/widget tests. No live endpoint, APK, migration, or publication has been performed. Model tests are synthetic only. Dart formatting/analyzer and actual UI verification must pass before merge.

Added on-device ID-only favorites/history (latest 100), clear history, bounded text scale, and horizontal four-school comparison. Lists resolve only against current published catalog, so saved IDs alone cannot show withdrawn content. Uses existing preference allowlist, no network tracking. Original formatter failures were addressed from CI's exact diff; newly authored Dart still needs formatter/analyzer verification. System share, complete nested field display, adaptive comparison accessibility and widget tests remain. No release.

## Server contract implementation (FIQH-DEV-07)
The dedicated GET/HEAD feed is implemented in hosting/admin/fiqh-public.php, gated by migration 4 and explicit private setting public_enabled=true. It defaults off and returns 404 until an operator deliberately activates it after staging, legacy review and release approval; no seed or migration enables it. Approved immutable revision plus matching publication event are required; latest drafts are never queried for public display. Nested allowlists strip private reviewer, audit, and editorial metadata. Hidden category trees and unpublished related IDs are excluded. ETag/304, 4 MiB maximum and existing client cache contract are implemented. Some optional nested fields have only conservative bilingual-list projection pending final schema validation; public web detail pages, SEO, cache revocation and full integration tests remain outstanding. No production setting changed. Exact formatting diff from CI for prior Flutter files applied.

## Public web pages
Added server-rendered AR/EN indexes and issue pages under /admin/fiqh/{ar|en}/ and /admin/fiqh/{ar|en}/{slug}/, plus /admin/fiqh/sitemap.xml. They consume the exact published projection and activation flag as the JSON feed; unpublished or withdrawn slugs return 404. Includes canonical and alternate language URLs, titles, descriptions, Open Graph metadata, responsive CSS, semantic sections, escaped user content, and no client scripting. Routes sit under /admin because the existing Hostinger deployment already packages top-level PHP/CSS/.htaccess; no new public directory or credentials needed. Search engine discovery from the root site, system share, accessibility verification and production activation remain outstanding. CI formatter passed previously; analyzer's unused refresh result warning was addressed by explicit invalidation and read. Await fresh CI before merge.

## Issue sharing
The catalog requires unique stable slugs as well as IDs. Public issue URLs are constructed only from the fixed HTTPS origin, locale and validated slug. Android reuses the existing madar/share native text chooser; missing or failed native channel falls back to copying title and link (including on iOS until native support is implemented). No private content or reading history is included. A previously cached issue may have a link that returns 404 after withdrawal; sharing is not a fresh server verification. The public activation switch remains off. Tests verify localized link construction and rejection of draft/unsafe slugs. Device-level share testing is still required.
