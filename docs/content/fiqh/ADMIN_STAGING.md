# FIQH-DEV-03 — staging editor slice

The existing authenticated admin route section=fiqh_editor presents a separate staging view of the new tables (legacy fiqh stays unchanged). It is inaccessible without existing admin session and CSRF protection. The view is inactive unless migrations 1 and 2 have already been applied explicitly. No auto-migration, approval, publication or public route exists. Draft writes use the authenticated user ID; the existing role table allows owner, reviewer and editor for draft actions only. The generic publish/restore actions are rejected on the staging editor route. The old fiqh route remains intact and requires its own migration and hardening before new public content is enabled.

Implemented: overview planned/created/draft/new published counts, editable category and source JSON records, category filtering and 50-item pagination, issue editor with bilingual plain-text fields for general and school positions, structured JSON for evidence/analysis/other position fields, source ID reference list, completeness indicators for saved revisions, raw saved draft preview and revision history metadata.

Not yet implemented: complete guided forms for nested data, actual 14-tab UI, autosave, unsaved-change guard, preserving all form input after validation failure, searchable source/related selectors, duplicate title detection, revision diff, mobile rendering preview, detailed category progress, qualified review lifecycle and publishing. Existing legacy content is not migrated. Do not enable on production before staging tests and migration review. Use synthetic fixtures only.

## Editor improvements
The draft issue form now preserves raw submitted field values (even invalid JSON) and its original revision lease after an unsuccessful POST, warns on unsaved edits when leaving the page, supports explicit source selection with bilingual citation locators, and compares historical immutable content and frozen sources against the latest revision. Metadata forms still use JSON and do not yet preserve failed submissions. Source picker requires JavaScript; manual JSON remains available. Browser interaction has not been independently verified. No autosave or publication has been added.

## Guided evidence and optional autosave
Added guided evidence creation (Quran ranges, hadith bibliographic locator, bilingual evidence, source selector) into existing canonical JSON form. No quotations or citations are generated automatically. Existing issues can opt in to draft-only debounced autosave for the current page; creation remains manual. The authenticated endpoint requires the explicit checkbox, existing revision lease and canonical validation. An ambiguous network response or conflict stops further writes and requires manual reconciliation; it never retries or advances review form revisions. Review buttons are disabled after autosave until reload. The existing unsaved guard remains conservative. This is not offline recovery, a full field-by-field editor, or a verified browser experience. Added service tests; latest CI not yet verified. Applied exact Dart formatter corrections from Commit 16.
