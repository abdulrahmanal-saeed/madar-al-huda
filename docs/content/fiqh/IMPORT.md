# FIQH-DEV-05 — draft import foundation

Schema version 1 envelope: {schemaVersion:1, issues:[{operation:"create"|"update", expectedRevision:0|positive integer, issue:{...canonical issue body}}]}. Maximum 50 issues or 2 MiB per transaction. All IDs/numbers/slugs must be distinct within a batch. Create requires revision 0; update requires the exact current revision. Under the same transaction, preview executes the draft-save path and rolls back every write, including audit events. Commit repeats validation and requires the exact preview token, bound to actor, payload and resulting revision hashes (including frozen source metadata). The token is a consistency check, not authentication; caller must authorize and explicitly confirm. No review or publication fields are accepted at top level. No public content is changed. An already-applied create/update is rejected as a stale revision rather than duplicated. An exact no-op update is safe.

Export returns up to 50 latest canonical drafts and revision leases, not approval state. Import supports only issue records, with existing categories and sources, and relations to existing or earlier-created issues; forward/cyclic issue links in a single batch are not yet supported. Structural draft validation is partial and does not imply scholarly completeness. No HTTP/MCP endpoint yet. Remaining: durable request idempotency receipts, CSV metadata parser, source/category bulk operations, nested strict validation, admin preview/confirm/export UI and MCP integration. Test fixtures are synthetic only.

## Admin and MCP integration
Authenticated admin includes a preview/confirm form (JSON or metadata CSV), and private JSON/CSV downloads in 50-record pages. Admin input limit is 512 KiB. CSV exact UTF-8 header: id,number,slug,categoryId,title_ar,title_en; create-only, never overwrites a full draft. CSV export is spreadsheet-safe reporting, not a lossless roundtrip (formula-like values are escaped); use JSON for exact editing. MCP exposes eight structured draft-only tools, checks migration availability, rejects unknown arguments, binds previews to stable MCP key ID, and requires explicit ownerConfirmed plus exact preview token for commit. Existing authenticated MCP dispatch/logging is reused; owner confirmation is a client/operational requirement, not independent cryptographic user authorization. Configure the write tool as Always ask. No MCP review, publish, or archive capability exists. The general publication path remains separate. Full nested validation, durable idempotency receipts, forward references, bulk metadata operations and browser/integration verification remain outstanding. No production migration or connector deployment was made.
